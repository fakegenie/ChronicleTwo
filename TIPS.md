# Compiling and matching tips

Notes for getting C++ to match retail with MWCC `3.0-011126` (`-O3,p`). The
first three sections are how this tree builds, checks and gates functions. The
rest summarises the compiler behaviour found in the sibling checkout's README
and in our own merge work. Each compiler tip is a technique that moved a
function, so confirm it in the unit you are editing.

## Build and check

- `./build.sh` builds and verifies the linked image against retail.
  `CLEAN=1 ./build.sh` throws `build/pal` away first and `JOBS=8` sets the job
  count. The result must read `SCES_511.90: OK` with every section OK.
- `./dev.sh <command>` runs a command in the build container. Files the
  container creates are root-owned, so delete them with `./dev.sh rm -rf ...`
  (for example `ps2/asm`).
- `./dev.sh python3 scripts/build/check_objects.py [unit] [-v]` checks every
  unit's object against retail without linking: pieces, sizes, bytes with
  relocation fields masked, and relocation targets. It names the failing
  function, so start there when the image check fails.
- The linker script places units back to back with no absolute addresses. One
  function with the wrong size shifts everything after it, so a failing image
  usually has one real culprit near the first difference. Fix the first failing
  unit and function, then rebuild.
- To see every failing unit at once, run the build with ninja's `-k 0`
  (`cmake --build ... -- -k 0` inside `scripts/build/cmake.sh`). Without it the
  build stops at the first failed object.
- `./diff.sh --report` writes the objdiff report to `progress/report.json` and
  prints the totals. `./diff.sh <mangled symbol> -o - --format json` gives one
  function's match percent and instruction diffs. `python3 scripts/re/coverage.py`
  counts matched functions, guarded drafts and asm-only functions per unit.
- The asm in `ps2/asm` is generated by the split. After changing which
  functions are `INCLUDE_ASM`, remove `ps2/asm` and rebuild so the split
  regenerates. A stale split gives `File includes ASM ... that does not exist`.
- mwccgap's `Elf` class crashes on objects that mix compiled functions with
  `INCLUDE_ASM` stubs (`IndexError` in `function_names`). `setup_mwccgap.py`
  applies `scripts/build/patches/mwccgap-elf.patch` on every build, which is why
  `tools/mwccgap` shows as modified. `postprocess_object.py` and
  `check_objects.py` both need it.
- `scripts/build/postprocess_object.py` repoints compiler-numbered statics,
  jump tables and literal pools at retail's names and sorts each object's
  sections into retail's address order. Without it, vtables and some data come
  out wrong even when the instructions are right.

## Gating conventions

A function is in one of four states:

| State | Source form | Built from |
| --- | --- | --- |
| Matched C++ | plain definition | the compiler |
| Draft | `#ifdef NONMATCHING` body `#else` `INCLUDE_ASM(...)` `#endif` | retail assembly |
| State-matched | `#ifdef STATEMATCHING` body `#else` `INCLUDE_ASM(...)` `#endif` | retail assembly, then checked and spliced by `state.py` |
| Asm only | `INCLUDE_ASM(...)` | retail assembly |

- The marker is `INCLUDE_ASM("ps2/asm/pal/nonmatchings/<unit>", <mangled name>);`.
  `INCLUDE_RODATA` and `INCLUDE_BSS` do the same for data.
- When a function does not match, gate it instead of leaving the build broken.
  Wrap the body in `#ifdef NONMATCHING` with the `INCLUDE_ASM` in the `#else`.
  Keep the body, since it is the draft someone continues from.
- A gated function that other code calls by its C++ name still needs a
  declaration. Keep a `static` or plain prototype above the marker
  (`fishingobj` `GetTriPose`).
- A gated function can drop things the compiler emitted for it. Examples are
  an inline function it instantiated (`editmenu` `CCharaFrameMatching::Initialize`
  appears after `MenuRemovalInit` and needs its own `INCLUDE_ASM`), a `.ctor`
  table (`snd_mngr` had `INCLUDE_RODATA` for it as well as the compiler's own
  copy, giving two pieces), or literal pool entries. `check_objects.py`
  reports these as a missing piece, an extra piece, or an unresolved `at_NNNN`.
- Compiler-numbered literals (`@2420`, renamed `at_2420`) shift when an earlier
  function stops being compiled. Later functions that rely on the numbering
  then fail with unresolved `at_NNNN` targets. Gate the dependants too, or use
  the state mechanism below.
- Delete an `INCLUDE_BSS` or `INCLUDE_RODATA` placeholder only when no
  remaining `INCLUDE_ASM` function references it (grep
  `ps2/asm/pal/nonmatchings/<unit>/`).
- Retail's file-local copies, with `__2` or `__3` suffixes in
  `main.symbols.txt`, are `static` in the `.cpp`. A global definition fails
  at link. The reverse also happens: `gameutil`'s `def_vrtx` is referenced by
  `libdev` assembly, so it has to be a plain global.
- Functions whose bodies are only VU0 vector and matrix code have no C form
  in most cases. The `mg_math` ones are written as `asm void f(...) { .set noreorder
  ... jr ra; <delay slot> }` and match at 100%. `mgZeroVector` does have a C form:
  `*(u_long128 *)vector = 0;` compiles to the retail `sq $0, 0($4)`.

## Compiler state and `state.py`

MWCC carries state from one function to the next within a file, so a function's
code can depend on code that the plain build never compiles.

- A 64-bit divide emitted earlier makes later float-to-int casts keep `a0` and
  `a1` free and use `a2` and `a3`. A `u64` division placed before the first
  function reproduces it. Symptom: a correct body whose temporaries sit in
  `a2`/`a3` in retail and `a0`/`a1` here. The fix is `primer=u64div`.
- Earlier drafts compiled as C set state for later functions. Symptom: a draft
  matches with its neighbours present but not once they are `INCLUDE_ASM`. The
  fix is `drafts`. dng_effect `Init_Wind` and `Init_Fire` match only while
  `Init_Cold` is compiled as C.
- Literal numbering has the same dependency (see above).

`scripts/build/state.py` handles this. For units listed in
`ps2/config/pal/state_units.txt` (`<unit> [drafts] [primer=<name>]`),
`mwccgap.sh` compiles the unit normally, then `state.py` compiles it again with
the unit's options and `-DSTATEMATCHING`. It splices in each function that
exists in both objects and whose code or own data differs. `drafts` turns every
`#ifdef NONMATCHING` block whose `#else` holds only `INCLUDE_ASM` lines into live
code for that second compile, and those functions are never spliced. Because
only functions present in both objects can be replaced, the plain build keeps the
`INCLUDE_ASM` stub for every `STATEMATCHING` function.

- Use `STATEMATCHING` for a function that matches only with the unit's state
  options. Use `NONMATCHING` for a draft that does not match at all.
- Every unit with a `STATEMATCHING` block needs a row in `state_units.txt`. The
  row's presence also makes `state.py` and objdiff compile the unit that way.
- Test an option against the whole unit. An option that changes any matched
  function is wrong for that unit. In `menuchr`, adding `drafts` to the primer
  broke a matched function, so it uses the primer alone.
- Editing an earlier draft can change later matched functions in a `drafts`
  unit. Rebuild and run `check_objects.py` after every draft edit.
- objdiff pairs functions by symbol name. The compiler writes template arguments
  as `mgRect<f>` and `PrimQuad<f>`, while the split names them `mgRect_f_` and
  `PrimQuad_f___`. `scripts/build/objdiff_config.py` maps those names in
  `symbol_mappings` (`template_names`). A new template argument that is not
  `mgRect<f|i>` or `PrimQuad<f|i>` needs its own mapping, or the function shows as
  asm in the report even though the bytes verify.
- A matched function that contains a switch jump table can come out of the report
  with no score, because the table's local labels split its row.
  `scripts/re/coverage.py` counts a `STATEMATCHING` function with no score as
  matched. A plain C++ function is matched when its asm is under
  `ps2/asm/pal/matchings`.

## Merge lessons

- Text changes that are meant to be neutral can break a state-compiled match.
  Master's cleanup commit changed
  `((CBaseMenuClass *)this)->SetTexBlock(texBlock)` to `SetTexBlock(texBlock)`
  and replaced extern `__ct__` wrappers and typed raw-pointer constructors with
  real constructors. That broke `menuchr` and `menusys`. To find the offending
  edit, diff the good and bad versions and bisect or greedily re-apply the hunks,
  checking one unit at a time with a single-unit compile plus
  `check_objects.py <unit>` (about ten seconds).
- Moving mangled externs to header prototypes can fail to compile. A body that
  calls `GetHalfFontNo__Fc(...)` or `GetItemDataType__Fi(...)` needs the extern
  declaration, or the call renamed to the header's name.
- When a function is ambiguous between overloads, add casts. `SetStack(stack++,
  elapsed / 3600)` with a `u64` argument matches both the `int` and `float`
  overloads; cast to `int`.
- An inline constructor declared in a header can make the compiler call
  `__ct__...` through an `extern "C"` declaration where master's source calls
  the real constructor. Match whichever form the retail call site uses.
- Moving a block of the file changes line numbers but not code. Comments never
  changed codegen in our tests.

## Types, locals and control flow

- Check prototypes before tuning instructions. A `char`, `s8` or `u8` return
  type can add caller-side sign extension or masking that retail lacks. Update
  headers and definitions together and check every consumer.
- Pointer types affect scheduling. Use the existing element types and named
  fields instead of `void *` conversions.
- Match load width and signedness. Compare `lb` with `lbu` and `lh` with `lhu`.
  Casting a character read to `s8` gives the signed load without changing the
  buffer type.
- Local declaration order, scope, initialization timing and loop-index reuse all
  change registers and stack slots. A random or exhaustive sweep over declaration
  order found perfect matches in a few dozen tries. Give each loop its own index.
- A named pointer keeps an address in a saved register. `CCPoly *polys =
  poly_buffer;` before the first use of a large local array stops MWCC from
  rematerialising it with `lui/addiu`. A local alias to a global costs a saved
  register, so use the global directly where retail does.
- Index at every use when retail shares address arithmetic. Cache a pointer only
  where retail keeps one.
- A named value before a call fixes argument evaluation order. For
  `stSetBuffer(stack->stGetTop(), stack->stGetRest())`, retail computes the rest
  first, so it becomes a named local.
- Stack layout: 16-byte objects and large arrays go first in declaration order,
  small arrays after. A temporary passed directly to a call, such as
  `mgRect<float>(...)`, lands in a different group from a named local.
- Small `s16` or `s8` locals that are not narrow in retail cause `dsll32/dsra32`
  shifts and spills. Declare them `int`.
- Float comparisons keep their polarity: `!(a < b)` and `a >= b` differ for NaN.
  Keep retail's comparisons, repeated calls and null checks.
- `(int)x` and `fptosi(x)` place values differently. Under `primer=u64div` only
  the cast responds to the helper-call state.

## Branches, switches and loops

- An `||` guard with a bare `return` copies the epilogue
  (`bnez; nop; b epilogue+4; ld ra`). Separate `void` guards compile to a plain
  branch. For value-returning guards the behaviour is the opposite in menusys.
  Check retail's branch targets before rewriting.
- A switch disables fallthrough delay-slot filling for the whole function.
  `#pragma schedule off` is the wrong tool for unfilled slots.
- An empty `if` is dropped. `switch (x) { case A: case B: break; }` keeps the
  branch.
- Case labels are compared in reverse source order. Read retail's compare chain
  backwards to recover the source order. An ascending `bne` chain that falls
  into each body is an `if`/`else if` chain.
- A compare chain with bodies in source order is a switch, including
  `x == 4 || x == 3`. A `default:` placed between cases explains a dead
  `b epilogue; nop`.
- Comparison spelling selects the branch: `x > c` gives `slti at,x,c+1` with a
  separate branch, `x >= c + 1` gives `slti v0`. Constant-on-the-left forms
  (`0 < x`) give `slt at` compare-and-branch. `if (x)` and `x != 0` differ.
- `for (;;) { if (c) break; ... }` is a top-tested loop, while `while` rotates
  to a bottom test. A loop's exit code written inside the loop places the exit
  block before the body, as retail does.
- `argc >= N` often needs `argc > N - 1`.
- A function that returns a stale `v0` in retail is `void`.

## `new`, constructors and inline depth

- Retail tests `new`'s result in `v0` when the pointer need not survive a call.
  Natural `p = new (buf) T` matches when the result goes straight to a global,
  a field, or a return. Otherwise write the allocation by hand with the
  assignment inside the condition:
  `if ((p = (T *)operator new(sizeof(T), buf)) != NULL) { p->Initialize(); }`.
  Out-of-line constructors become `p = __ct__...(p);` through an `extern "C"`
  declaration.
- MWCC inlines three nested inline calls and emits a call at the fourth.
  `#pragma inline_depth(N)` with `#pragma inline_depth reset` raises the limit
  for one function. Under `inline_depth(0)`, an inline constructor's `new` gives
  retail's `beqz sN; nop; jal __ct`.
- A header constructor can change already-matched callers and emits a weak copy
  in every unit that needs it. Define the inline constructor in the one `.cpp`
  where retail has it.
- Typed globals generate initializers and constructor entries. Define them in
  retail's order and let MWCC generate `__sinit_<unit>_cpp`. Constructing them
  with placement `new` adds null tests retail lacks. Replace the BSS,
  initializer and `.ctor` placeholders together.
- The vptr sits where the first virtual function is declared, after members
  declared before it. Check offsets with `STATIC_ASSERT`.
- `#pragma divbyzerocheck on` is needed in some functions. Scope it with
  `#pragma divbyzerocheck reset` after them.

## Floats, constants and data

- Constant load order follows the order of the statements that use the
  constants. Place pointer assignments where retail issues them, and try a named
  float local per argument.
- A float written as an int literal changes hoisting (`PrimQuad(tex, 0, 24)`).
- `if`/`else` with float constants gives integer `sw` stores. A ternary gives FPU
  stores.
- An `extern` declared before the first `#include` can reorder float constants
  in earlier functions. Keep it directly before the include that needs it.
- Brace-initialised local arrays and structs emit anonymous literal templates
  (`at_NNNN`). A zero-initialised `float rates[2] = {0.0f, 0.0f}` produces one in
  `.sbss` or `.bss`. Declare the array in the block where retail copies it.
- Aggregate spelling changes copy instructions. A bitfield struct returned
  through a hidden pointer gives `ld/sd`. A `struct { u_long128 value; }` copies
  with `lq/sq`. `RECT t = F();` and `RECT t; t = F();` differ.
- A struct-typed member (bitfield struct, union, `struct { u_long v; }`) is
  copied through an address register in an implicit copy. An anonymous union
  whose first member is a `u_long` copies with a direct `ld/sd`, which is how
  `mgCTexture` holds `tex0`, `tex1` and `clamp`.
- `sceGsTex0` has no `operator=`. `ReloadTexture` calls retail's
  `__as__9sceGsTex0FRC9sceGsTex0` helper through an `extern "C"` declaration.
- Qword rounding is `if (bytes & 0xF) q = (bytes >> 4) + 1; else q = bytes >> 4;`.
  Signed `x * 16 / 16 + 1` matches `Alloc` sizes where `sizeof` does not.
- Reading an extern rodata quadword as `*(u_long128 *)&sym` gives retail's early
  `lui/addiu` setup.
- Unrolling counts expression nodes. For a float loop to unroll by 8, read the
  neighbours through one element pointer.

## Tools

- `./decompile.sh <symbol>` runs m2c on the retail assembly for a first draft.
  Regenerate the context with `./dev.sh scripts/build/cmake.sh ctx` after header
  edits.
- `scripts/re/draft.sh` and `scripts/re/draft_check.py` compare drafts with
  retail.
- The sibling checkout also has `match.sh` (needs the migrated-unit pipeline),
  `permute.sh` (mutates a draft body and scores each variant against retail's
  words) and `imgdiff.py` (word-level image diff by section). None of those are
  in this tree.
- `./dev.sh python3 scripts/re/progress_md.py > PROGRESS.md` regenerates
  `PROGRESS.md`. It compiles each unit's drafts live (and `STATEMATCHING` bodies
  the way `state.py` does), runs objdiff against retail, and lists every gated
  function with its match percent, differing instruction rows and size.

## Additions from parallel matching

- A `pcpyld` in retail can come from a 128-bit integer literal such as `packet[6] = 0x000000000000086E3000000000008001;`. MWCC accepts these literals, while 128-bit shifts fail with "illegal data size".
- `mgAbs` from `mapload.hpp` is the inline behind a bool-to-unsigned-to-float chain. Including it fixed `OverlapPoly3XZ` and `HumanShrowMoveIF`, and `mgAbs(a) > mgAbs(b)` matched where `!(a <= b)` did not.
- Retail inlines `sync; ei` where a draft calls `EIntr()`. Write `asm { sync ei }` on each exit path.
- A named local for a call argument (`SetRotation`'s rotation) stops a constant staying in a saved register across the call.
- Moving a null check before the first dereference changed scheduling in `CheckInventItem`.
- `diff.sh` diffs the last object that compiled. When a draft fails to compile or the gate edit is off by a line, it reports the old score silently. Run `./dev.sh scripts/build/cmake.sh objdiff` and check the exit code.
- `check_objects.py` does not recompile. Run `./build.sh` first.
- objdiff scores a function with jump tables near zero because it splits at the case labels. Compare against the concatenated retail pieces instead.
- `#pragma optimization_level 2` is needed for `mgCTextureManager::ReloadTexture(int, u_int *)`.
- Declaring a parameter as `sceVu0FVECTOR ground` instead of `float *` fixed a stack slot in `GetFootPoly` with the same mangled name.
- Retail's brace-initialised local arrays (an `at_NNNN` template followed by element stores) are written as brace initialisers with non-constant elements, such as `int next[2] = {waku_pos[0], waku_pos[1]};`. Template copy plus assignments makes MWCC hold the array addresses in registers where retail does not.
- A function containing an if/else whose two branches store the same value the variable already holds, so the compiler deletes both stores, switches on retail's "no fall-through delay-slot fill" style in menusys switches.
- Writing a call argument as a named local before the call, and reordering locals with a permutation search, are the usual last steps once the structure is right.
- Unrelated header edits can change a matched function's scheduling. Adding a single member declaration to `mgCTexture` broke `CRain::Start` in the `scene` state compile. Declaring `view_angle` before `position` made it match with every header variant tried.
- MWCC keeps a value in a caller-saved register (a1 to a3) across a call only when the callee is a static function defined earlier in the same file. `GetScreenSize` in mglib, `GetFishParam` in fishing and `FishDist` in gyoracesim had to be `static` for that reason.
- Retail leaving a0 and a1 unused for temporaries is the sign of the `primer=u64div` state option. `gyoracesim` needed it added to `state_units.txt`.
- Member-wise copies of struct-typed members (bitfield structs, unions, `struct { u_long v; }`) go through an address register. An anonymous union whose first member is a `u_long` copies directly with `ld`/`sd`, as retail does. `mgCTexture` `tex0`, `tex1` and `clamp` are declared that way.
- Hand-written `operator new` plus manual vtable stores, with all allocations before the `Initialize()` calls, matched `StepDataLoading`. The same pattern is in `fishing.cpp`, `dynCOLLISION` and `LoadEditCursor`.
- Early returns on each failure path matched where nested ifs did not (`StepDataLoading`).
- Retail copies two `s8` fields with `lb`/`sb`, while a two-byte array copies with `lbu`. `BASE_MONSTER_TBL::escape_rate` is two `s8` fields for that reason.
- `perm.py` must score drafts with the unit's primer and `drafts` options as `state.py` does. The copy in `ps2/re/a71/perm.py` with `PERM_EXPAND=1` agrees with the real build. Put a space after a bracket before a `[[[` choice.
- Renaming a member in a header can break a matched function in a state-compiled unit that includes it (`scene`, `CRain::Start`). Build and check every unit after a header rename.
- Extra `nop`s at branch targets mean the block structure differs from retail. In `CreatRoom`, moving `info_no = pick;` from inside a do-while to after it removed them. In `RoomLink`, an abs written as a ternary inside the call argument (`(int)(d < 0.0f ? -d : d)`) did the same.
- When retail computes every input of a subtraction up front, MWCC is folding a single-use local into the expression in our build. Using the same expression twice (`dist_x = (float)(src_x - goal_x); ... dx = src_x - goal_x;`) stops the fold and restores retail's load order.
- A second induction variable in retail (an inner offset reloaded from an outer one on each pass) came from `while (cond) { for ... }` where the draft had `do { for ... } while (cond)`.
- Large struct locals that retail places below the char arrays: declare the arrays in the inner blocks that use them instead of hoisting the struct, which also moves its constructor call.
- Retail can inline only part of a header inline (`CTreasureBoxManager::Initialize`). When stores are missing at the end, write the partial loop in the caller.
- A hill-climb over which locals are hoisted to the top, and in what order (add, remove, swap, move one declaration per step), finished `LoadDungeonMapFile` where random sampling had stalled. Check that every generated variant compiles; a broken template scores like a bad variant.
- Restore order in the epilogue (f-regs versus s-regs) follows control-flow structure. `if (p == NULL) { return; } else { body }` fixed `DrawEsaDropRoot`, while `if (p != NULL) { body }` and a plain early return with a flat body did not.
- Splitting an expression into two statements (`right = x + w; right = 2.0f + right;`) changes float register colouring without changing instructions (`PictureDraw`).
- A fresh block-scoped index (`for (int k = 0; ...)`) per loop can fix an index/offset register swap where reusing `i` does not (`InitUkiObj`).
- When a brace-initialised local replaces an `extern at_NNNN` template copy and the template lives in `.sbss`, keep the `INCLUDE_BSS(at_NNNN, ...)` placeholder. Postprocess points the compiler's own template at it; removing it fails `check_objects` with a missing sbss piece.
- An unused local declaration, or `} else { }` after an early return, can change register colouring. It is a cheap knob for a permutation search.
- `./dev.sh` does not pass environment variables into the container; use `./dev.sh env VAR=1 python3 ...`.
- The perm.py word-diff score misleads when an instruction is inserted or removed, because everything after shifts. Read the diff with mode `-1`.
- `asm {}` blocks inside a function are emitted in source order. Operands must be pointer variables: a local array fails with "could not be assigned to a register" and `this->member` with "illegal addressing mode". For inline VU0 macros, declare the pointer locals first and assign them in a separate statement in reverse order (`out = lw_matrix; left = parent_matrix; right = local;`). That reproduced retail's `addiu` order where initialised declarations did not.
- Fully hand-written functions with loops, `addi` marked as handwritten, and their own `jr ra` (`mgVectorMinMaxN`, `mgApplyMatrixN`, `mgApplyMatrixN_MaxMin`) match as `asm void f(...) { .set noreorder ... jr ra; <delay slot insn> }`, using register names a0 to a3, t0, t1 and a plain label. An `asm {}` block in a normal function gets rescheduled, or loses the `jr` delay-slot fill under `schedule off`.
- VU0 float-to-int conversion through a stack array (`Color`, `Vertex`) matches as `int converted[4]; int *out = converted; asm { lqc2/vftoi/sqc2 }` followed by the call with `converted[i]`.
- A global's base reused for several fields (`mgInsideScreen`) needs `mgRENDER_INFO *info = &mgRenderInfo;`.
- When retail's loop counters start after the loop guard, in the preheader, the source multiplied the index (`x * 16`) and MWCC strength-reduced it. A hand-written `tile += 16` counter does not match (`setImageTag`).
- In movie.cpp, `DmaAddr()` and `UncAddr()` choose between the `and`-with-mask and `dsll32/dsrl32 4` forms depending on context. `((u_long)p << 36) >> 36` is a different, wrong sequence. A bitfield passed through `(u_int)(int)` gives retail's sign-then-zero-extend pairs.
- `inside = a > b; if (inside)` gives retail's `slt reg; beqz reg` where a direct `if` gives `slt at`. `MIN`-style ternaries like `(remaining > len) ? len : remaining` give retail's `slt; beqz; nop; b; nop; move` shape.
- perm.py fails silently when the template does not compile. Write the compiler output to a file and read it. Generate `build/re/manifest.tsv` with `./dev.sh python3 scripts/re/manifest.py -o build/re/manifest.tsv`.
- A one-line `static inline` accessor (`GetActiveEventMap()`, `Align16Blocks`) changes register colouring even when the instructions are identical. When registers are rotated and declaration order has no effect, wrap the call or expression that defines the mis-coloured value in an inline. This matched `_FUNC_POINT_GET_ROT` and `CFuncPointMngr::Reserve`.
- Reusing an existing variable for a later result, and declaring a fresh loop counter first among the locals, changed the s-register assignment in `CheckMonsterTolk` where renaming and moving declarations did not.
- Compiling a function that does `new T[n]` emits T's weak inline constructor. Remove that constructor's `INCLUDE_ASM` stub, or `check_objects` reports an unexpected piece while the image check still passes.
- A local declared directly in an unbraced `case` gives a different constant-load order than the same code in a braced case (`FishModifyParam` case 5).
- Bash in the worktrees refuses a python heredoc followed by `./dev.sh` in one command. Put generator scripts in files and run them separately.
- An increment written inside a call argument (`PrintDirect(x, y += 0x12, ...)`) stops MWCC constant-propagating the counter. Retail's `addiu s0,s0,N` before each call comes from this (`DrawEventEdit`).
- A redundant `if` that assigns a variable the value it already holds (`int step = 100; if (select == 1) { step = 100; }`) switches on retail's unfilled delay-slot style. It also leaves a dead `lw`/`li` compare pair and keeps the constant in a saved register (`MenuLoop`). Look for an orphan compare in retail to find where it goes.
- Reusing named float locals, declared once at function top and reassigned before each use, changed float constant load order where per-block locals, literals or declaration order did not (`DrawMenuTopic`).
- Declaring a loop temporary outside the loop (`int glyph_x;` before a `do` loop, assigned inside) fixes callee-saved register colouring when strength-reduced induction pointers take the wrong registers (`DrawActiveFont`).
- A call evaluated once before an if/else that uses it in both branches is a named local before the `if`.
- Retail's `x - (x / 5) * 5` (a subtract instead of a second divide) comes from a named quotient (`int part = rest / 5; ... rest - part * 5`).
- For a jump-table function use perm's word count or an aligned diff, not the objdiff percent: `MenuMainInit` was 13 words off while objdiff reported 44.9%.
- In perm.py templates `[[[[` (an array subscript followed by a choice) mis-parses. Put a space after the bracket.
